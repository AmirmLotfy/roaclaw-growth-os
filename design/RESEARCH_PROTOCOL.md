# Mandatory Mobbin / Refero research and design documentation

The user has connected Mobbin and Refero to Codex. Use the tools if available; do not fabricate research calls. Inspect actual returned screens/flow images and metadata. Save IDs/links and a brief 'take / avoid' note in `design/RESEARCH_OUTPUT.md`. Research should influence hierarchy and flow, **not** result in copied visual designs or third-party assets.

## Queries to run on Mobbin
- Web / desktop B2B dashboard with dense but readable reporting and filtering.
- Advertising campaign or analytics table, filter, date range, data provenance and error states.
- Agency/client multi-workspace navigation, client switching and settings.
- Approval, destructive action confirmation and event history.
- Browser side-panel and compact task-oriented assistant, command palette, overlay.
- Account onboarding, permissions and connection status.
- Pricing/plan comparison, authentication and invitation flows.

Use `search_screens`, `search_flows`, `search_sections` as supported. Examine image output; don't rely only on generated labels.

## Queries to run on Refero
- `refero_search_styles`: restrained editorial b2b SaaS, precise enterprise reporting, warm neutral UI, operator console.
- `refero_search_screens`: client switcher, audit report, campaign list, sources with citations, multi-step agent task approval, activity timeline.
- `refero_search_flows`: agency onboarding, connection permissions, create report, review and approve action.
- `refero_search_sections`: original typographic SaaS hero, product showcase using actual screenshots, feature explanation, privacy section.
- `refero_search_sites`: research Linear, Attio, Mercury, Sentry and contemporary analytics/ops products as functional references only, not designs to clone.

## Deliverable matrix
At least 12 distinct screen references, 6 flows, and 6 landing/website section refs if results are available; if unavailable, record tool errors and research feasible subset. For every reference capture: product, source URL/ID, screenshot (if permissible), observed navigation hierarchy, interaction pattern, usefulness, what NOT to imitate, copyright note.

## Design decisions record
Write a decision log for: selected identity, nav model, evidence+action split view, sidebar density, user permission dialogs, semantic colors, type scale, empty states, motion, RTL handling, extension width and visual QA. Each must link to a research observation or to a documented product reason.

## Do not use
Downloaded logos, original interface screenshots as ROACLAW marketing assets, unlicensed stock art, replicated competitor page structure, official competitor names in product UI, or made-up reference IDs.
