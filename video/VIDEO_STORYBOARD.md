# ROACLAW — 170-second hackathon video storyboard

**Master:** 1920x1080 16:9, 30 fps, English narration/captions, sound-on and understandable muted, total target 2:50 and HARD maximum 3:00. Mandatory real product screen capture throughout. The first 30 seconds should communicate what the app does AND demonstrate actual hybrid AI, per contest FAQ.

## Visual treatment
Show the running app with the captured cursor and a restrained crop. Use the same IBM Plex typography, navy `#132642`, ink `#14243D`, cool canvas `#F4F7FB`, and blue signal `#1853D8` as the app. Chapter cards and captions identify each action in plain terms. Audio uses clear narration and an original unobtrusive score when supplied.

## First-30-seconds non-negotiable
Do not spend 25 seconds on problem and logo. Actual `ON_DEVICE` AND cloud/fallback behavior must be visible early. If local call takes longer due to model download, pre-download the model BEFORE recording, then capture a genuine subsequent inference.

## Capture plan
Record independently: (A) 1440x900 dashboard full-screen; (B) Chrome with extension side panel and fixture page; (C) on-device SDK visible inference source; (D) cloud source; (E) bookmark readback; (F) live microphone interaction (if working); (G) scheduled follow-up; (H) optional browser developer tools showing redacted source. Avoid recording secrets, addresses, customer information or personal accounts.

## Editing notes
Make on-screen captions 54px-ish within 1080p safe margins; use actual DOM/accessible UI text readable at normal playback size. Use source data citations with small but legible labels. Do not animate real metrics to invented values. Show `Demo data` watermark when relevant. Title frames should be short and useful. Aim for crisp editing and 1-2 strong product moments, not nonstop motion.

## Contingency
If voice not working, change voice shot to a real typed command; edit VO to omit voice claims. If extension pairing not working, do not show impossible combined screen. If Nano local not verified, product is not submission-ready for hybrid claim: prioritize fixing before video rendering.
